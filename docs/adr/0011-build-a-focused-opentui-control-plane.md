# Build a focused OpenTUI control plane

The Control Plane will be a new Bun, TypeScript, OpenTUI, and Solid application that selectively reuses MIT-licensed OpenCode interaction patterns and components. Muxvia will not fork the full OpenCode session and agent product, because its interface is a focused provider and routing console rather than a coding-session host.

All actions will be named commands bound through one centralized, layered keymap and a single topmost-overlay stack; component-local global keyboard handlers are not an independent command path. `Esc` closes the top overlay or navigates back. `Ctrl+C` requests Control Plane exit and confirms first when an editor is dirty. Every exit path restores the terminal, and exiting the Control Plane never stops the Routing Service.

Matching the pinned OpenCode interaction shell, the interactive Control Plane uses OpenTUI's alternate screen by default and preserves the upstream `OTUI_USE_ALTERNATE_SCREEN` environment override; it never uses split-footer mode. Its root always follows the actual terminal dimensions. There is no global minimum-size gate or `Terminal too small` blocking page: individual screens responsively fold columns, hide secondary regions, wrap, or scroll according to their own content. Extremely small terminals receive best-effort rendering and a no-crash guarantee, not feature-equivalent layout.

The accepted visual baseline treats a Target CLI as OpenCode treats the current session or context. Home uses a centered Muxvia identity, one action prompt, contextual hints, and a sparse footer. A Target view is a continuous status-and-activity stream with a fixed action prompt; it keeps Mode, Current Target Provider, Serving Provider, Routing Service, Managed Configuration, and the applied snapshot or plan visibly distinct. Provider, route, account, activity, and system operations open through named commands, slash commands, dialogs, or focused detail routes rather than persistent product navigation.

The Control Plane deliberately excludes an application bar, top-level section tabs, a permanent navigation sidebar, dashboard card grids, and a global status strip. Its visual grammar follows the pinned OpenCode shell: one monospace scale, terminal-cell spacing, dark background and panel fills, semantic color used sparingly, left-rail emphasis, bare shortcut text, and undecorated overlay panels. A wide-screen sidebar may show context for the current Target CLI only; it is never product navigation. Muxvia retains its own identity and domain language, so this is adoption of OpenCode's interaction and visual grammar rather than a pixel-for-pixel product fork.
